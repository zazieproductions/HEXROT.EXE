# Decoder Adapters

Adapters live in `backend/decoders/adapters.py`. Each adapter has a fixed ID and executable name, version probe, fixed argument array, and parser for its own output. Executables are resolved only from allowlisted system/package-manager directories. Users cannot supply an executable or shell string through the API. Input paths are generated by the workspace and mounted read-only into the sandbox.

To add an open-source decoder, add a fixed adapter and version probe, construct argument arrays without a shell, implement bounded output interpretation, and add tests using real fixtures. Confirm that the OS sandbox exposes only necessary executable/library paths and still denies networking and unrelated user files. Update the compatibility matrix and document whether the tool decodes audio or merely inspects headers. Do not interpret an ordinary nonzero exit as a crash or vulnerability. Signal status is obtained by the in-sandbox supervisor.

FFmpeg's `hash` muxer reports a SHA-256 of decoded output; ffprobe and `sndfile-info` do not produce comparable decoded-output hashes in these adapters. Invocation records use the sandbox input path or `<INPUT>` placeholder; reports redact the host workspace path. Reproduction must use the same sandbox and limits as the recorded job.

Some versions of `sndfile-info` exit zero even when the input cannot be opened. Its adapter checks the actual error text and requires reported channel and sample-rate fields before recording acceptance; ambiguous output is labeled unknown rather than accepted or rejected.
